Active Directory Domain Services (AD DS)

O que é, para que serve, quais dores reais de negócio ele resolve e como transformar o Windows Server no cérebro da rede corporativa.

Carga: 3 horas Serviço de Diretório Identidade Corporativa Single Sign-On

Navegue com ← → ou utilize os botões no canto inferior direito.

Conceito Fundamental

O que é o Active Directory?

O Active Directory (AD) é o serviço de diretório da Microsoft que armazena, organiza e controla o acesso a todos os recursos de uma rede corporativa.

01

Banco de Dados Central

Um repositório seguro e distribuído (arquivo ntds.dit) que registra usuários, senhas, grupos, computadores, impressoras e servidores.

02

Provedor de Identidade (IdP)

O único órgão validador da rede: se o AD autorizar, o usuário entra; se o AD recusar ou a conta estiver bloqueada, nada na empresa é acessado.

03

Mecanismo de Governança

Permite aplicar políticas de segurança e configurações simultâneas em 10 ou 10.000 computadores sem encostar fisicamente neles.

O Problema Real

A Dor do Administrador: A Vida SEM Active Directory

Nas Aulas 07 e 08, criamos contas locais no compmgmt.msc. Agora imagine essa realidade em uma empresa com 50 funcionários:

O Caos do Grupo de Trabalho (Workgroup)

  • Múltiplas Senhas: Se Ana mudar de máquina, a senha dela não existe lá. O técnico precisa cadastrar Ana manualmente em cada PC.
  • Demissão de Funcionário: Para revogar o acesso de um ex-colaborador, a TI precisa sentar em todas as 50 máquinas para apagar a conta dele.
  • Vulnerabilidade Crítica: Nenhuma garantia de que os computadores usam senhas fortes ou telas bloqueadas.
  • Sem Rastreabilidade: Não há log central de quem logou onde ou quando.

A Solução: Domínio Active Directory

  • Cadastro Único (1 segundo): Cria a conta ana.financeiro no DC01 e ela pode logar em qualquer computador da empresa.
  • Revogação Imediata: Um clique em *Disable Account* no DC01 corta o acesso da pessoa a todos os computadores, arquivos e e-mails instantaneamente.
  • Políticas em Massa (GPO): Trocar a exigência de senha de 8 para 12 dígitos leva 30 segundos para a empresa inteira.
Experiência do Usuário

Single Sign-On (SSO): Uma Chave para Todas as Portas

Sem o AD, o funcionário tem que digitar usuário e senha para o Windows, outra senha para a pasta de arquivos, outra para o sistema e outra para o Wi-Fi.

Com Active Directory (Autenticação Kerberos v5)

O usuário senta pela manhã, digita sua credencial de domínio uma única vez e ganha um Ticket de Concessão de Bilhete (TGT).

Login no Windows 10 → Ticket Kerberos emitido pelo DC01
├ Acessa pasta \\DC01\Financeiro → Entra direto sem pedir senha
├ Abre o ERP corporativo → Reconhece o usuário automaticamente
└ Conecta à impressora de rede → Imprime com sua cota corporativa
Arquitetura de Diretório

A Hierarquia Lógica: Floresta, Árvore e Domínio

Nível 1

Floresta (Forest)

O limite máximo de segurança e autoridade da organização. Compartilha o mesmo Catálogo Global (GC) e esquema de diretório.

Nível 2

Domínio (Domain)

A fronteira administrativa principal. No nosso laboratório: nexatech.local.

Define as políticas de senha e armazena os objetos da empresa.

Nível 3

Unidades Organizacionais (OUs)

Subpastas dentro do domínio para organizar setores (TI, Financeiro, Vendas) e computadores.

O Servidor

O que é o Controlador de Domínio (Domain Controller)?

O Controlador de Domínio (DC) é o servidor físico ou virtual que roda a função AD DS e hospeda a réplica do banco de dados.

O Banco NTDS.DIT e a Pasta SYSVOL

  • NTDS.DIT: O arquivo de banco de dados baseado em Jet Database Engine onde residem todas as contas, hashes de senhas e objetos.
  • SYSVOL: Pasta compartilhada na rede onde ficam os scripts de logon e as diretivas de GPO replicadas entre os DCs.

Boas Práticas de Mercado

Regra da Redundância: Em ambientes de produção reais, NUNCA existe apenas um DC. Sempre implantamos no mínimo dois Controladores de Domínio (DC01 e DC02) com replicação mútua para tolerância a falhas.

Engenharia de Protocolos

O Trio que faz o Active Directory Funcionar

ProtocoloPortaFunção no Active Directory
DNS (Domain Name System) 53 (UDP/TCP) O GPS do AD. As estações não acham o DC sem ele. Registra registros SRV vitais como _ldap._tcp.dc._msdcs.nexatech.local.
Kerberos v5 88 (TCP/UDP) O Segurança. Emite bilhetes criptografados (Tickets TGT). A senha do usuário nunca viaja pelo cabo de rede.
LDAP / LDAPS 389 / 636 (SSL) O Catálogo. Protocolo de busca usado por aplicações, e-mails e sistemas para consultar a lista de usuários e permissões.
Procedimento de Recuperação

Atenção: A Senha DSRM (Directory Services Restore Mode)

Durante o assistente de promoção a DC, o Windows solicitará uma senha especial de DSRM. Por que ela é crucial?

Para que serve o DSRM?

Se o banco de dados ntds.dit for corrompido, se houver um ataque de ransomware ou falha catastrófica de boot do AD DS, o servidor não conseguirá logar com contas comuns do domínio.

A Senha DSRM é a chave-mestra de emergência que permite iniciar o Windows Server em modo de restauração segura e reparar o Active Directory offline.

Anote essa senha no seu caderno de laboratório!

Laboratório Prático

A Missão de Hoje no Laboratório

  1. Conferir IP estático 192.168.10.2 e DNS local 127.0.0.1 no servidor.
  2. Instalar a função Active Directory Domain Services no Server Manager.
  3. Executar o assistente e Promover o Servidor a Controlador de Domínio.
  4. Criar a floresta raiz com o domínio nexatech.local.
  5. Definir a senha de DSRM e concluir a instalação.
  6. Reiniciar o servidor e validar o primeiro login corporativo como NEXATECH\Administrator.

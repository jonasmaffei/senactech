Fundamentação Teórica

Por que a comunicação em rede é em camadas?

Sem camadas, um navegador web precisaria saber exatamente se você está em um cabo de rede de fibra, Wi-Fi 6 ou sinal 5G.

01

Modularidade

Se você troca uma placa de rede Ethernet por uma placa Wi-Fi, o seu navegador e as aplicações web não precisam ser reprogramados.

02

Mecânica de Funcionamento

Encapsulamento: Como o dado viaja

Pense no encapsulamento como colocar uma carta dentro de vários envelopes sucessivos até chegar ao carteiro.

1. Aplicação
[GET /index.html HTTP/1.1] (Mensagem original criada pelo navegador)
2. Transporte
[Porta Origem: 54321 | Porta Destino: 80] + [Dados HTTP] (Gera o Segmento TCP)
3. Internet / Rede
[IP Origem: 192.168.10.100 | IP Destino: 192.168.10.10] + [Segmento TCP] (Gera o Pacote IP)
4. Enlace
[MAC Origem: AA:BB:.. | MAC Destino: CC:DD:..] + [Pacote IP] + [FCS Verificação] (Quadro)
5. Física
01101001 01110100 00100000 01110010 01100101 01100100 01100101 ... (Pulsos elétricos ou de luz no cabo)

No receptor ocorre o processo inverso: o Desencapsulamento (removendo cabeçalho por cabeçalho até entregar o payload ao Apache/Nginx).

Camada 3 · Internet

A Camada de Rede e o Endereçamento IPv4

A camada de rede é responsável por encontrar o caminho e entregar o pacote do host de origem até o host de destino final (Roteamento).

Estrutura do Endereço IPv4 (32 bits)

Dividido em 4 octetos: 192.168.10.100 /24

  • Parte de Rede: 192.168.10.0 (identifica a sub-rede local).
  • Parte de Host: .100 (identifica a máquina específica).
  • Máscara: 255.255.255.0 (/24) - diz onde termina a rede e começa o host.

Como o host decide para onde enviar o pacote?

Se o IP de destino estiver na mesma rede local:

O pacote vai direto via switch usando o MAC Address obtido por ARP.

Se o IP de destino for de uma rede diferente (ex: 8.8.8.8):

O pacote é obrigatoriamente enviado ao Default Gateway (Roteador/pfSense) para ser encaminhado.

Camada 4 · Transporte

TCP vs. UDP: Qual a diferença prática?

TCP (Transmission Control Protocol)

Orientado à conexão e confiável. Estabelece uma sessão antes de enviar dados.

  • Handshake de 3 vias: SYN → SYN-ACK → ACK.
  • Garantia de entrega: Se um pacote cair, o TCP retransmite.
  • Controle de ordem: Pacotes chegam numerados e são organizados.
  • Exemplos: Páginas Web (HTTP/HTTPS), Compartilhamento (SMB), SSH e RDP.

UDP (User Datagram Protocol)

Sem conexão e rápido (Best Effort). Envia sem confirmação de recebimento.

  • Sem Handshake: Dispara os dados imediatamente sem aviso prévio.
  • Sem Retransmissão: Se perder pacotes, a aplicação decide o que fazer.
  • Baixo overhead: Cabeçalho minúsculo (apenas 8 bytes contra 20+ bytes do TCP).
  • Exemplos: Resolução de nomes (DNS), Configuração de rede (DHCP), Streaming e VoIP.
Camada 4 · Multiplexação

O que é uma Porta e o que é um Socket?

Um servidor com um único endereço IP pode rodar dezenas de serviços simultâneos. As portas são os "ramais" que diferenciam quem recebe o quê.

Portas Bem Conhecidas (0 - 1023)

Reservadas para serviços padrão e exigem privilégios de administrador para escutar.

Exemplos: 22 (SSH), 53 (DNS), 80 (HTTP), 443 (HTTPS), 445 (SMB).

Portas Efêmeras / Dinâmicas (49152 - 65535)

Usadas pelo sistema operacional do cliente para abrir conexões de saída temporárias.

Ex: O Windows sorteia a porta 53120 para falar com a porta 443 do servidor web.

O Conceito de Socket

Um Socket é o par exato que identifica univocamente qualquer conexão na rede:

IP:Porta Origem ↔ IP:Porta Destino
192.168.10.100:54201 ↔ 192.168.10.10:443
Protocolo em Foco · DHCP

Como uma máquina obtém IP: O Processo D.O.R.A.

DHCP opera sobre UDP nas portas 67 (servidor) e 68 (cliente) usando broadcast.

Passo 1

Discover

Cliente → Broadcast

"Quem é o servidor DHCP? Não tenho IP ainda! (0.0.0.0 → 255.255.255.255)"

Passo 2

Offer

Servidor → Cliente

"Olá! Eu sou o servidor 192.168.10.10. Posso te emprestar o IP 192.168.10.101 com máscara /24."

Passo 3

Request

Cliente → Broadcast

"Aceito formalmente a oferta do servidor 192.168.10.10 para usar o IP 192.168.10.101."

Passo 4

Acknowledge (ACK)

Servidor → Cliente

"Confirmado! O IP 192.168.10.101 é seu por 8 dias, gateway 192.168.10.1 e DNS 192.168.10.10."

Protocolo em Foco · DNS

Como funciona a resolução de nomes (DNS)

O DNS converte nomes amigáveis (como app.nexatech.local) no IP numérico que o roteador compreende. Utiliza porta UDP 53 para consultas e TCP 53 para transferências de zona.

Tipos de Registro Fundamentais

  • A: Aponta um nome de domínio para um IPv4 (ex: app → 192.168.10.20).
  • AAAA: Aponta um nome de domínio para um IPv6.
  • CNAME: Cria um apelido/alias (ex: www → app.nexatech.local).
  • PTR: Resolução reversa (converte IP de volta para nome).
  • SRV: Localizador de serviços (crucial para o Active Directory localizar o DC).

Hierarquia de Resolução

  1. O cliente checa o seu cache DNS local e o arquivo hosts.
  2. Consulta o servidor DNS local configurado (ex: DC01 em 192.168.10.10).
  3. Se o domínio for interno (nexatech.local), o DC01 responde autoritativamente.
  4. Se for externo (google.com), o DNS local faz encaminhamento (forwarding) para a internet.

Hands-on · Comandos

Ferramentas Práticas de Inspeção

Como ver o que está acontecendo na pilha de protocolos na prática:

No Windows (Prompt / PowerShell)

# Ver tabela de conexões ativas e portas em escuta:
netstat -ano | findstr :80

# Testar se a porta TCP de um servidor está aberta:
Test-NetConnection -ComputerName 192.168.10.10 -Port 445

# Consultar resolução de nomes no servidor DNS local:
nslookup app.nexatech.local 192.168.10.10

No Linux (Ubuntu Server)

# Inspecionar sockets TCP e UDP ouvindo (listening):
ss -tulpn

# Testar handshake de porta via terminal:
nc -zv 192.168.10.10 22

# Diagnosticar DNS detalhadamente com dig:
dig @192.168.10.10 app.nexatech.local
Análise de Tráfego

Identificando as Camadas no Wireshark

Ao abrir uma captura de pacote no Wireshark, você vê a árvore de encapsulamento refletida linha por linha:

▸ Frame 1: 454 bytes on wire (Camada 1: Física / Bits capturados)
▸ Ethernet II, Src: 08:00:27:12:34:56, Dst: 08:00:27:65:43:21 (Camada 2: Enlace / MAC Addresses)
▸ Internet Protocol Version 4, Src: 192.168.10.100, Dst: 192.168.10.10 (Camada 3: Rede / IPs)
▸ Transmission Control Protocol, Src Port: 51234, Dst Port: 80, Seq: 1, Ack: 1 (Camada 4: Transporte)
▸ Hypertext Transfer Protocol, GET /index.html HTTP/1.1\r\n (Camada 7: Aplicação / Payload)

Essa árvore comprova que a pilha teórica é exatamente o que está trafegando pelo cabo da rede.

Pergunta de Reflexão

"Por que uma porta necessária para o serviço pode, ao mesmo tempo, ser a maior vulnerabilidade do servidor?"

Dica: Pense no serviço SMB (porta 445), fundamental para a rede local da empresa, mas causador da proliferação global do ransomware WannaCry quando aberto para o mundo.

Fechamento

O que aprendemos hoje

  • Camadas e Modularidade: O modelo OSI orienta o conceito e a pilha TCP/IP executa a comunicação no mundo real.
  • Encapsulamento: Os dados ganham cabeçalhos (Portas → IPs → MACs) na descida e perdem na subida.
  • TCP vs UDP: TCP assegura integridade via 3-way handshake; UDP entrega alta velocidade e baixa latência.
  • Portas e Sockets: Identificam com precisão cada serviço em execução nos servidores.
